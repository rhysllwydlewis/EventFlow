# Supplier dashboard: what is left

This file used to list about a hundred things that were not done, not verified or left alone after the
dashboard redesign (rhysllwydlewis/EventFlow#1819). **Everything that can be done in the code has been done, or
decided with a reason.** What is left below needs a person with access that the code and its tests cannot
have: production data, a payment account, real devices, a lawyer, the hosting dashboard.

Ids (`B-…`, `K-…` and so on) are the original ones, so older notes still point somewhere.

## 1b. Done in the dashboards PR (was on the owner list)

- **O-1, C-6 privacy wording** written and `POLICY_PRIVACY_VERSION` moved to 1.5 (display-only; nothing prompts users). Profile-view events now expire after 400 days (TTL index plus a background backfill for older events).
- **C-1 outbox warning:** the mail fallback no longer writes any address, subject or body to disk; the end-to-end test reads the email from a test-only in-memory route.
- **E preview safety:** previews named `EventFlow-pr-N` refuse live Stripe keys and send no real email unless a recipient is on `MAIL_PREVIEW_ALLOWLIST`.
- **CDN / `req.ip`:** production sits behind Cloudflare then Railway. The server now trusts Railway's hop plus Cloudflare's published addresses, so `req.ip` is the visitor (rate limits, the per-address view cap and audit logs depended on it).
- **Tips versus Next steps:** tips now only give advice the checklist cannot (live enquiries, reviews, plan limits, admin notes, calendar gaps).
- **Analytics:** the Google tag no longer receives what a visitor typed (search words, postcode).
- **V-7 automated pass:** keyboard and accessibility-tree walk of both dashboards, budget and guests found and fixed 14 defects (calendar dialogs trapped Tab and lost focus, calendar day buttons said "undefined", unread counts were never spoken, bell dropdown focus, enquiries drawer focus, focus hidden by the fixed bottom bar, no skip link, live notices not announced, retry buttons dropping focus, label-in-name failures, and more). Not fixed: repeated "View/Photos/Pause" buttons on package rows (in `app.js`), notification badge contrast (site-wide `navbar.css`), the vendor Jade widget, footer link height (43px).

## 2. Decided, and why

These were questions rather than defects. Each has an answer; say if you want a different one.

| Id       | Decision                                                                                                                                                                                                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| K-2      | **Public-calendar publishing stays "supplier category, unless an admin overrides it for that supplier".** The per-supplier override already is the entitlement flag. A plan-based gate would take the feature away from some suppliers, which is a pricing decision.                                                            |
| K-5      | **The enquiry-quality badge, reasons and filter are back** (from the existing lead scoring, worked out when read, shown as an estimate). **The reply-time distribution chart is not**: the dashboard shows the reply rate and median reply time, and a distribution would need every reply timed and stored.                    |
| K-8      | **A price stays free text** ("From £450", "£25 pp"), because that is how suppliers think of it. The number in it is read by one parser (`parsePriceAmount`, shared by the browser and the server), and price filtering and sorting use that number. A stored amount/currency/unit would need every supplier to re-enter prices. |
| K-9      | Plan limits on windows and package counts come from the server's plan config and the page reflects them; the explanatory text is generated from the limits, so there is nothing to keep in step.                                                                                                                                |
| C-2      | The visitor's own planning data (plan list, start choices) is kept because they asked for it. The two interface flags for the welcome card are only remembered with functional consent.                                                                                                                                         |
| S-2      | The messenger widget polls whatever happens to the live connection, so updates never stop; a "live updates off" label would only add noise.                                                                                                                                                                                     |
| S-3      | The dashboard only follows links on this site (or Stripe's hosted pages for billing). A supplier's own website link is shown as a link they can open; the dashboard never navigates the page to an address it was handed.                                                                                                       |
| T-4, T-9 | Browser files that are not modules are tested by cutting the function out of the source (`app.js`'s redirect code, the cookie-choice helper). Moving the redirect allowlist out of `app.js` would mean a new script tag on every page that loads `app.js`; the helper throws a clear error if the markers move, so it was left. |
| R-1, R-3 | Review of the whole repository and of every older test was not part of this work. What was reviewed: every file the dashboard uses, the security review of the routes it calls, the price and messenger code paths, and the dashboard stylesheet.                                                                               |

## 2b. Decided in the supplier-dashboard audit

| Id    | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AUD-1 | **The Availability card was removed, not wired up.** `suppliers.availability` was read by no customer-facing page or API, so the control was a placebo. Showing it publicly would need the profile, search and structured data to agree on one meaning: a product decision. Stored values stay.                                                                                                                                                                                                                                                                                                                                     |
| AUD-2 | **`blurb` still counts for the completeness 'description' check** although the About section does not show it (only an admin can set it; the browser widget counts it, and a parity test keeps the two in step). Dropping it from both is the way to make the check match the page exactly.                                                                                                                                                                                                                                                                                                                                         |
| AUD-3 | **Counted profile views are capped at 20 per network address per supplier per hour** (was 5 in the first draft). It stops one client minting visitors by changing its User-Agent; a very busy shared address (a large venue, a mobile carrier) can still undercount. Set the `PROFILE_VIEW_IP_CAP` environment variable to tune it (it is an environment change, so it needs a restart, not a code change). The cap is an atomic counter in `profile_view_caps` (anonymous visitors only), not a count of stored events.                                                                                                            |
| AUD-4 | **The visitor key is now an HMAC-SHA256** (under `PROFILE_VIEW_SALT`, or else `JWT_SECRET`) of the address and browser family, truncated, so a stored key cannot be reversed by trying every address; an IPv6 address counts as its /64. No address-derived value is stored on events, and the per-address cap lives in short-lived counter rows (about two hours). Rotating the secret makes every visitor look new once.                                                                                                                                                                                                          |
| AUD-5 | **The CSV export has no limiter of its own** beyond the site's general limits. It is read-only and capped at 1000 rows per source, so it was left.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| AUD-6 | **A supplier can still reply to a review of their own that is pending or rejected** (the reply is invisible until it is published) and the reply route does not check `approved`. Harmless; left.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| AUD-7 | **The public-calendar edit of an already published event needs no new approval** (design limitation; an approved event's content can change).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| AUD-8 | **The old messenger `NotificationBridge.js` was deleted, not loaded.** No page loaded it, so the `messenger:notification` event it dispatched never fired. `NotificationBridgeV4.js` is the maintained bridge (it dispatches a different event). Loading the old one as well would poll the conversations API twice and start bell notifications nobody has tested. The three listeners for that event (`notifications.js`, `messaging-notifications-stabilisation.js`, `MessengerWidgetV4.js`) are inert and were left, to avoid re-stamping a script that loads on most pages; remove them the next time those files are touched. |
| AUD-9 | **The customer dashboard and `/budget` keep two labelled definitions of "committed".** The dashboard adds listed package prices (and says how the figure splits); `/budget` counts only the budget lines the customer entered, and its footnote says so. Package prices are indicative asking prices, so folding them into a figure the customer edits would blur plan and quote. Revisit if customers ask for one number.                                                                                                                                                                                                          |
