# Supplier dashboard redesign: everything not done, not verified, or left alone

Written at the end of the work on rhysllwydlewis/EventFlow#1819 (branch `claude/supplier-dashboard-redesign`) so
that later PRs have one place to pick items up. It lists what was **not done**, what was **out of scope**, what
was **found and left alone**, what was **not tested or verified**, **known problems**, and **what was not
reviewed**. It does not list what was fixed; the PR description does that.

Each item has an id (`B-…`), why it matters, where it is, and a suggested next step. Priorities: **P1** fix soon
(security, data, or something visibly broken), **P2** worth doing, **P3** nice to have or a decision. Anything
marked _unverified_ is a belief that was not checked.

Update this file as items are done: strike them through or delete them in the PR that fixes them.

## 3. Known limitations that need server work or a product decision

These are features the old dashboard did not have either, or things the page cannot do because the server does not support them. The dashboard says so honestly in each case; none are bugs introduced by this PR.

| Id  | Item                                                                                                                                                                                                                                                                                                                                                                          | Pri |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| K-1 | **Suppliers are not notified of enquiries and cannot reply in-app.** Quote requests and contact-form messages are stored against the supplier, but there is no email/push to the supplier and no reply path. The drawer lets them mark read/handled/new only. A supplier can sit on a lead for weeks without knowing. Needs a notification (email at least) and a reply flow. | P1  |
| K-2 | **Public calendar publishing is hard-coded by supplier category plus an admin override**, not an entitlement/plan flag. The dashboard has to say "isn't available for your supplier type". An entitlement flag in the plan model would be correct.                                                                                                                            | P3  |
| K-3 | **The package list API is approval-gated.** Suspended or unapproved suppliers get 403 from `/api/me/packages`, so they cannot see packages they already created. The page avoids the request and says why, but the supplier still cannot see or edit them.                                                                                                                    | P2  |
| K-4 | **The old public review reader ignores v2 reviews.** Reviews stored in the newer shape appear on the supplier dashboard but not on the public review reader. (Dashboard handles both shapes.)                                                                                                                                                                                 | P2  |
| K-5 | **Lead-quality overview and the response-time distribution were not restored.** The server sends no score and no distribution, so the badges are hidden and the chart omitted. Needs a server source (see `docs/LEAD-SCORING.md`) before the UI can come back.                                                                                                                | P3  |
| K-6 | **Setup-guide progress is per browser, and now only stored when cookie consent allows functional storage.** It does not follow the user across devices and resets if consent is withdrawn. A server field (e.g. `user.onboarding.supplierGuide`) would fix both.                                                                                                              | P3  |
| K-7 | **Visit counts** exclude the supplier's own visits, admins, crawlers and unknown/unapproved suppliers, and count a visitor once per hour. Page-load counts, not people. The page footnotes this; there is no unique-visitor measure and no bot score beyond the user-agent list.                                                                                              | P3  |
| K-8 | **Prices are free text** (e.g. "from £450", "£25 pp"), 60 characters. There is no numeric price, currency or unit, so the platform cannot sort or filter packages by price reliably, and the customer dashboard has to regex-parse the text (`customer-dashboard-home.js`, `parsePrice`). A structured price (amount, currency, unit) is the right long-term fix.             | P2  |
| K-9 | **Supplier plan limits for dashboard windows (7/30/90 days) and package counts** are enforced by the server's plan config; the page only reflects them. If plan config changes, the explanation text in the page may need updating. Not a bug.                                                                                                                                | P3  |
